# Traceability canonical

The canonical projections: documents and manifests derived from the runtime
authorities (the root policy and the semantic owners), byte-bound to them by
the hash-binding registry. A projection is regenerated from its authority,
never hand-edited.

## What each file does

- `harness-requirements.md` — the canonical requirements ledger: the
  normative requirements with their stable `REQ-*`/`DER-*`/`USR-*` source
  IDs. Its bytes are hash-bound into `src/kernel/requirements.ts`.
- `slice-declarations.json` — the canonical slice declarations the slice
  verifiers resolve through.
- `handoff-protocol-manifest.json` — the conformance projection of the
  handoff protocol authority, regenerated by
  `engine/scripts/regenerate-handoff-manifest.ts`.

## Where it lives and what consumes it

The folder lives at `engine/traceability/canonical/`. The hash-binding
registry, the slice verifiers, and the handoff suites consume these
projections.
