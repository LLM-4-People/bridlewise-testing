# git

The `engine/test/git/` folder of the development surface.

## What each file does

- `declared-deletions.test.ts` — the declared-deletion primitive on planted repositories: a declaration records path, HEAD's blob, HEAD, HEAD's move count and the ignored copies (the machine-local excludes included) in the checkout's own git directory and changes neither the tree nor the index; `git rm` can be declared, a path with anything on disk (an in-place untracking, a symlink) cannot; a folder, a pattern, a second spelling, an absolute path and an empty call are each a typed refusal, all or nothing; the shared HEAD reader answers exactly the asked paths (a folder asked with its own file); the one state rule and the guard's verdicts (exact path only, copies changed, expired); a `reset --soft` back to the declared commit leaves it stale for good; a file that came back expires its declaration and the next change drops it; consumption after a commit, a stale leftover re-bound only by declaring again, a mismatched one after an edit; a torn record and a record copied from another checkout are typed and `clear` withdraws either; a linked worktree's declarations stay in its own git directory; the CLI's literal paths, `--paths-file`, `--paths-file-nul`, `--` and an empty file; the status verb fails on any declaration that is not pending; twelve parallel declares all land and a clear racing declares never resurrects what it withdrew.
- `git-adapter.test.ts` — the `git-adapter.test` module.
- `git-executable-platform.test.ts` — the `git-executable-platform.test` module.
- `git-hostile.test.ts` — the `git-hostile.test` module.
- `index-baseline.test.ts` — the live index baseline: only staged blobs HEAD does not hold are protected and pinned; `rm --cached`, `restore --staged` and `reset` are drift and the one repair restores `git ls-files -s` byte for byte even after `gc --prune=now`; a stray add, a commit of another path and a commit of the protected path are not drift and HEAD moving advances the record (a writer does; `harness index status` and the signal's summary only read, leaving the record and its pin untouched); the repair never reverses a commit, never removes an entry, refuses a missing blob untouched, keeps intent-to-add, takes `\n`/leading-quote paths; conflict stages are not protected; a garbled record is typed.
- `stage.test.ts` — `harness stage`: changed tracked files and named new paths staged, nothing unnamed; a glob-like name literal, an absent one refused rather than matched; badly spelled, missing and folder names refused with the index untouched; a protected staged blob and a drifted index refused; `ws create` printing the stage command.
- `flake-cause-fixes.test.ts` — a `Flake-cause:` trailer explains a flaky-memory suspect only with its recorded reproduction, only when the fix changed a declared cause's MEANING (the test's own file may be the cause; a comment or layout edit, an untouched cause or an unjudged kind explains nothing, said by name), and only failures that measured the fix's parent bytes at every declared path AND said a reproduced digest; a statistical record explains only at the configured N and a record that shows nothing is refused by its schema; a moved test clears only by a recorded move into the live suite's manifest; an absent path, a forged record, a recurrence, a run with no tree or no digest reds; a malformed trailer is refused at the commit-msg door and, in history, reported and ignored.
- `flake-reproduction.test.ts` — the `harness flake` door: a test that failed on the parent and passed on the fix is recorded under the one set of conditions both sides ran under; a statistical reproduction runs each side N times (one parent failure, N fix passes, the counts and loads recorded); a pass on the parent, a fix failure, a skip that merely vanished or a cosmetic fix records nothing; a move is recorded only when the inventories show it; a credential never reaches a record; a refused or misnamed record is reported.
- `tree-reader.test.ts` — the tree readers: a commit's files with git's mode and object id, text read by batch (multi-byte after a binary blob, a symlink's target), a working tree as `git add -A` would commit it, and the tree writer building exactly its entries in a private index the repository never sees — concurrent writers and a crashed writer's leftover index never leak into a tree, a tree git cannot reproduce is refused, a non-UTF-8 path is refused, and every git call runs the configured executable under its ceiling.
