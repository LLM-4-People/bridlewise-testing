# promotion

The `engine/test/workflow/promotion/` folder of the development surface: the promotion primitive on real repositories whose branches are `dev` → `prod` (never this repository's names).

## What each file does

- `promotion-fixture.ts` — the fixture: a product (`prod`) and its development superset (`dev`) with a binary, a symlink, an executable, a hand-written lockfile with `bin` maps and an `npm:` alias, the profile, and the fixture's own command registry (a deterministic lockfile command that can answer like an npm cache miss; a gate with modes). Its LANDING mode adds what a candidate settles and commits: a setup with an ignored build output, a generator (`gen/pin.txt` and the pin of a hand-authored `tool/policy.ts`) that can oscillate, drift (a new value every pass) or write an undeclared path, the gate's failure modes (exit 1, past its ceiling with a child and a detached grandchild, ENOSPC, killed, writing a tracked file, printing its temp folder), a config document in the `tool` engine folder, and the repository's own pre-commit hook, which records where it ran and refuses on a marker.
- `apply.test.ts` — the build-and-commit stage (`apply --no-publish`): the happy build (parents, trailers, the settled tree, the hook in the candidate and its words, the refs, nothing published), T-C1..T-C10 (setup and the config mode, the converge fixed point and an oscillation, a stale and a pin-bearing generated output, a failing, errored, timed-out or writing gate, undeclared writes, no surviving process), T-K1 (a hook refusal), T-K3/T-K4 (no identity configured: S's committer and date; the same commit and receipt from an independent build under another HOME), the resume and the dropped pending (with its receipt), the exact target-edit list, the deletion budget, the unchanged short-circuit, the lock, the sweep of failed candidates, the retention of the profile's area, T-G3 (TMPDIR) and the verb's usage answer; the converge bound (a generator that never repeats), a failing setup, a pending built on an older target dropped, a missing target, and the typed failures a port injects (a git step the machine ended: `promotion_git_errored`, swept; git's refusal: `promotion_git_failed`; a candidate not holding P; a concurrent pin with its receipt removed; an error no code names: `promotion_unexpected` — each integrity answer keeping its candidate; a failing sweep never replacing the answer) and the derived ceiling; after every failure, the invariant sweep (T-K2).
- `promotion-fixture.ts` ADDS, for publication: an optional bare remote (`origin`, the dev and prod branches pushed), a linked checkout holding the target, and the fixture's view (`fixtureView`: the plan options the tests pass); `apply-support.ts` — the helpers every apply-driven test shares: `apply` (one run through the real `runPromotionVerb`, optionally from another checkout), `refused`, `landing`, `untouched` (no ref, worktree, index or checkout moved), `candidates`, `folderOf`, `receiptOf`, `committed`.
- `publish.test.ts` — publication (T-U1..T-U11): ONE atomic push (the commit, its receipt, a lagging source; never `+`), `ls-remote` verified, the target's checkout fast-forwarded with its unrelated edits kept, `--no-push`, a remote that moved (re-planned once, then `promotion_push_rejected`), a remote that refuses or is unreachable (the commit stays pinned; the rerun pushes the same one), a local target behind, ahead or apart, a source apart, parking on overlapping edits (exit 7, nothing touched, the rerun lands it without a rebuild), a locked index (`promotion_target_index_locked`, the lock kept), a torn fast-forward completed — and never over a version W staged that neither the old tip nor C records (it parks, the blob kept); a remote tip that carries C after the push (published) or does not (`promotion_post_publish_mismatch`); the receipt of a pushed commit kept when a stale pin is dropped; the resume after a published or landed run (T-R2, T-R4), latest wins through the entry's chain (T-R5: once the lock is released; a source pushed before the reconcile; a failed run; never a loop on a failing S; never after a hold or a coalesced run), `--no-publish` behind the remote moving nothing, direct edits handed back as a patch and the next plan after that patch lands (T-D1, T-D2, T-D4), the finish (the config mode, the build outputs installed in one transaction, `depsStale`: T-G1, T-G2), and the landing's git-step count against the derived ceiling.
- `crash.test.ts` / `crash-child.ts` — T-R1: an apply killed at each of its checkpoints (locked, reconciled, planned, candidate, settled, committed, receipt, pinned, pushed, landed, installed, finished) in a child process, then a rerun that finishes the same promotion — the same commit, published once, landed once, nothing left behind.
- `rollback.test.ts` — rollback and hold (T-H1..T-H4): a rollback restores an earlier promotion's tree with a new one-parent commit and its trailer, pushed with the hold; held, an unattended run answers `promotion_held` and a manual one refuses until `--release-hold --reason`; a rollback of a rollback, of the tip, or of a commit off the profile's history is refused; `hold` and `release-hold` on the remote (all or nothing); a rollback never reads or pushes the source (an unpushed or diverged local one), a failed rollback build leaves no hold, and a rollback whose push failed is resumed with its hold.
- `trigger.test.ts` — the trigger (T-T1..T-T4): the hook's text is the code's and never fails (git's `prepared` state, no node, a broken promoter), `auto` starts one unattended apply per triggered profile (a local hold is no reason: the run reads the remote's) and none for the promoter's own fetches and pushes, another remote's ref or a `manual` profile, each unattended run's own log (never truncated; removed once no record can point at it), the one notice line after a run that did not end ok, and the exit codes an unattended run answers with.
- `merge-guide.test.ts` — T-E3: `docs/process/MERGE-GUIDE.md`'s §7 code table holds every code of `codes.ts` once, with its class and exit code (and "auto 0" exactly for the codes an unattended run exits 0 on), and no other.
- `promoter-home.test.ts` — S's committed code promotes S (T-K5): where `apply` runs (clean at S, the variable, another repository's engine: here; dirty or elsewhere: the home; git's "no checkout" versus a machine failure), and the re-execution in the home at S (the committed promoter, the request's own flags with `--source S`, the variable), the home following S, the engine's own setup re-run when its inputs changed since the last PASSED preparation (a failed one is redone), the home's lock (an unattended run never waits for it), the chain of a home-placed unattended run launched by the top-level process after the child and the lock are gone, at the new S and in its own home, an occupied home folder, a child answering nothing or killed; and the REAL engine entry — both doors spawned, and `runInPromoterHome` re-executing it in a home whose engine folder is this engine.
- `projection.test.ts` — every path's reason (T-P1..T-P14): the untouched source projects to the target, a new reachable module ships, identities and modes are kept, an unreachable dev file does not ship and is advised, deletions and renames, the source's refusals, the deletion budget (exactly the fraction passes), companions, `up_to_date`, a gitlink, the target's direct edits with their patch, the never-rule, and purity toward refs, worktrees, the index and the checkout; the tree P is exactly the planned entries (a leftover index never leaks; a hostile `.git` entry is an integrity refusal), included modules are walked (H2), symbolic links and opaque edges, generated outputs and the target's regeneration, only this profile's first-parent promotions, an underived lockfile, only added paths advised, recipe paths, the plan id's inputs, a corrupt lockfile, and the most severe refusal answering.
- `transforms.test.ts` — the derived files (T-X1..T-X4): scripts and devDependencies narrowed, segments pruned, the exact bytes, a runtime dependency verbatim, the manifest refusals (a missing kept script, `&`, newlines, unspaced `&&`), the command word behind assignments and `npx`/`npm exec`, concurrent derivations in scratch of their own, and the lockfile command's memo, errored retries and failure.
- `profile.test.ts` — the profile's validation (T-P10) with the pointer of each violation (a derived path also excluded, a spawn base that is not a folder prefix), and the selection of a profile.
- `context.test.ts` — the context and the verbs: two declared profiles (every signal answers each; a verb with no `--profile` names the choice), the source's own profile over a stale HEAD, the target-trailer route, `status`/`explain`/`plan --diff` and each refusal's class, the audit line of every verb, the exit code of every class (usage errors are answers, `apply`'s override and reason rules included), the `--text` report, and the grammar's round trip (a request spelled back parses to itself).
- `exposure.test.ts` — the exposure (T-E2): unmeasured signals and typed refusals without a source, the source's answers with one, and a registration that imports no process code.
