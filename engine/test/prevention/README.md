## Where it lives and what consumes it

The folder lives at `engine/test/prevention/`.

The cache owners also exercise actual unavailable-source result-cache refusal:
eight isolated native-FS probes cover each caller's own and dependency bytes,
readable stale entries, memory/disk warmth, central diagnostics and recovery.
The governed owner covers actual malformed-source and oversized-AST early
returns; its parse owner reports both through the current parse diagnostic.
Native module fixtures expose NUL tuple aliases with differing executed values;
raw URL fragment tuples qualify memo framing separately. Literal extraction
checks dotted/empty property segments in both orders and mutation of nested
bindings and every freeze-boundary field. JSON value equivalence is the literal
contract; cold null-prototype objects and disk JSON objects are both accepted.

- `cache-value-admission.test.ts` poisons real owner-produced disk envelopes,
  clears result memory, checks full cold equivalence and proves valid disk hits.
  Architecture/lexical nested fields, raw JSON numeric overflow, S1 identity and
  flag consistency, governed strings and sparse literal bindings are covered.
- `filesystem-cache-diagnostics.test.ts` selectively faults native counter stat,
  trim enumeration/stat and publication rename for generic and S1 owners.
  It checks the fixed central signal exactly once, stable primary outcomes and
  unchanged destinations, with no raw secret/path leak. Atomic pre-try stat
  throws are retained as a separate required lower-owner contract repair.

The canonical JSON owner in `../json-integrity.test.ts` rejects absent own array
indices without consulting inherited getters, ignores overridden map methods,
and captures initial length before invoking own index getters. Capacity race
proof is retained under `research/responses-api/cache-value-diagnostics/`; its
repair requires a separately qualified concurrency authority.
