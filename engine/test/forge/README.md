# forge

The `engine/test/forge/` folder of the development surface: the forge
(`engine/src/workflow/forge/`). The client's tests run against a fake GitHub
on the loopback upstream, so every test drives the real outbound door and
transport; the projector's algorithm tests run against an in-memory
projection store.

## What each file does

- `fake-github.ts` — THE FAKE GITHUB every lane's forge tests use (not a test file): an object store by API path with ETags (a 304 is not counted) and `Link` pagination; the App flow (installation lookup and token minting with RS256 JWT verification against the App's generated key, manifest conversion); authentication; the pinned-version check; `refuseNext` (rate, secondary and plan refusals), per-test `route`s and the token lifetime. Tokens are assembled at runtime.
- `github-client.test.ts` — the GitHub adapter: the pinned version, media type and user agent; conditional GETs (304 from the cache, not counted; the bounded LRU); pagination and its required bound; every refusal classified once (budgets with their reset or wait, plan, permission, validation, server) with near misses; a redirect is `github_moved`; GraphQL errors; the API-path checks; credentials asked at call time.
- `app-tokens.test.ts` — the App registry (four Apps, least privilege, GitHub's permission names, custody), narrowing that never widens, the host key custody (0600 in the key home, identity without the key, environment Apps refused, malformed records refused) and installation-token minting (narrowed, cached, renewed before expiry; a token minted wider is an integrity stop).
- `fake-github-issues.ts` — GITHUB'S ISSUES on the fake GitHub, installed as its routes for one repository (not a test file): labels, milestones, issues (number, body, state and reason, labels, milestone, type), comments, sub-issues, dependencies and pins, with GitHub's answers (paginated lists with ETags and 304s, 404, 422 for a duplicate label or a second parent, `reopened`, the pin limit), the relations read through the GraphQL `issues` connection; `drops` plays a field GitHub silently does not keep.
- `github-store.test.ts` — the GitHub projection store on the real client: the first run builds every class (labels, milestones, issues with type, labels, milestone, sub-issue parent, dependencies, state, pin) and verifies it; V-25 (a second run writes nothing, its REST reads conditional); the reporter's text above the marker kept; V-28 (a dropped issue type is unverified); V-27 (a person's retitle proposed, then restored with a comment); a budget refusal typed and retryable, resumed by the next run; a person's issue and label never the projector's; a duplicate marker and a relation longer than a page refused typed.
- `projection-store.ts` — an in-memory projection store (`src/workflow/forge/projector/store.ts`) that keeps each object's git-owned fields, counts the writes, and plays GitHub's failure modes on demand: a field it silently does not keep, a refusal at the n-th write, an edit by someone else, an object someone else created.
- `projector.test.ts` — the projector: D's issues and labels with permalinks at S and the marker; V-26 by the kernel (the projection confined by the guardian: a computed-specifier dynamic-import write, a harness and a /proc read, a connect and a fetch to a live local server are refused and the server sees none; the clock and randomness are refused by computing twice; undeclared, built-in, literal-dynamic and bare imports are refused at link; a CPU spin meets its ceiling; a NODE_OPTIONS preload never runs; a host without the guardian is a typed refusal); the first run's phase order; V-25 (a second run makes zero writes; a changed record writes only its difference); V-28 (a silently dropped field is `projection_unverified`); the resumable budget refusal; a refused write; orphans (owned objects only: a person's label or issue never is one); blocked-by sorted whatever the input order; the input read from the commit, never the working tree; this repository's own projection; milestones and the milestone → workstream → task hierarchy with computed states; V-27 (a foreign edit to a label, a milestone and an issue under approval, auto and manual: proposed, restored with a notice, or reported; held until healed; judged per field: a field newly owned by git is written, one held field blocks neither the object's other changes nor another object, the proposal holds only the edited field; a deletion on GitHub proposed, recreated with a notice, or reported, never silently recreated); writes by phase before class; a first run adopts without calling anything foreign.
- `roadmap-feed.test.ts` — the roadmap data feed: computed states (a close shipped only when proven, claimed otherwise), milestone progress, the critical path through blocked-by, decisions with the items that carry them out; throughput by landing week and ETA bands only with enough history; a backdated close counted in its landing week and an input carrying a typed date refused; the per-landing history with first appearances, removals and decision-only landings; and the feed read confined from a scratch repository's first-parent history (a decision-only commit, a past spelling read as written, one digest per commit, an earlier commit's roadmap).
- `main-red.test.ts` — MAIN-RED: main's health is each workflow's row at the newest commit by ancestry (an older green appended after a newer red never hides it; a re-run answers by its last row), and a malformed row, another host's or repository's run URL and rows on diverging commits are refused typed; a red workflow is one open pinned Bug naming each failing test with its owner or UNOWNED, green again closes and unpins the same issue, a later failure reopens it; a run's texts are escaped (no code-span breakout, markup or `@mention`) and a body past GitHub's limit ends with a stable count of what it leaves out; the projection's input reads the ledger at its commit and the owners from the board at S.

- `apps.test.ts` — GH-1a: the App manifests, the `forge` section's refusals, and the generated `.github/forge/` files (drift named in two places, plus a near miss). The maintainer's `gh`: a secret on stdin only and typed failures without the value. The bounded run: input on stdin, a stall ended, a busy run ended by its CPU limit and never by a stall, and a slow talker kept alive. The Apps page against the fake GitHub, with each barrier red without it: the one-time token (no state without it), Host and Origin, and the conversion check (owner, name, permissions, events). Custody right after conversion: an environment key is stored before its push, held on failure and resumed on reload. A name already taken is detected. End to end: host custody, install links, and Done guarded by session and origin. A busy port is typed.

- `forge-key-home.ts` — the forge tests' key homes (a helper, not a test file): `temporaryKeyHome` creates a new, empty key home under the test process's own temporary root for every test that stores a key; `requireTestKeyHome` refuses to run unless the process is under the runners' private test key home.
- `flake-shim-token-ends-zero.ts` — a deterministic reproduction shim (registered in `testExecution.flakeReproduction.deterministicShims`): every `randomBytes` answer ends in a byte with a zero low half, recreating the one draw in sixteen that made the token test's near miss equal the real token.

## Where it lives and what consumes it

The folder lives at `engine/test/forge/`.
