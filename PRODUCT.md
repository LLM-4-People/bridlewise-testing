# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

People exploring Bridlewise for the first time, including visitors who do not know AI-harness terminology. They should understand a coding task, try an immediate example, and have a clear route to their own prompt and project.

## Product Purpose

Bridlewise is an open-source coding workspace that connects conversations, tools, changes, checks and decisions. The public experience must demonstrate that mechanism through understandable actions and visible outcomes. Canonical product wording and claims remain in [the brand sources](docs/brand/README.md).

## Operating Context

The public site is served by GitHub Pages. Its current demonstration is illustrative and offline. Genuine provider execution exists in the authenticated local web application. Public hosted execution requires a qualified backend and must never be implied by a replay, static prompt box or illustrative result. The live-path implementation remains open until an actual connected workspace is verified.

## Capabilities and Constraints

The redesign must support both an immediate guided interactive example and real own-prompt/code work through the existing runtime. Preserve existing provider, authentication, project ownership and execution gates. Readiness and admission are owned by the runtime/architecture manifests; this document does not override them.

Reuse the existing production Flow, inspector, transcript projection, rendering primitives, tool contracts and workspace state. Keep example provenance distinct from observed GitHub evidence and actual execution. No second harness, provider client or independently maintained transcript store.

## Brand Commitments

The name and mark are Bridlewise. The existing [design authority](DESIGN.md) and [shared token owner](src/cockpit/tokens.css) remain the starting point. The user explicitly requests novelty, ease of use, excellent UX, immediate responsiveness and power, and says the current homepage lacks impact and the demo is confusing.

## Product Principles

- Show the mechanism through a task, rather than beginning with internal terminology.
- Make the next useful action obvious; expose advanced controls progressively.
- Make interaction immediate, including on compact screens and with reduced motion.
- Keep actions, outcomes, evidence and capability limits truthful.
- Reuse canonical modules and generators; implement shared behavior at its existing owner.

## Evidence on Hand

The existing public record, production Flow demo and their published-source schemas provide authored example material. They are not live-AI proof or security admission. The exact UI and hosting gaps are retained in the current demo source review and live-route review outside the repository.
